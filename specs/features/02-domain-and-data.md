# Feature 02: Domain, persistence and dataset

## Overview

The entities of `01-domain-model.md`, their repositories and services, and the static dataset of `02-data-set.md`. No user interface. This epic is done when a test can place an order through the service layer and a dashboard query returns sensible numbers over the seeded data.

## Behaviour

### Persistence

Explicit `schema.sql`, Hibernate in `validate` mode, sequences starting at 10000. Repositories are Spring Data with JPA Specifications for anything dynamic. Services are the only transaction boundary and return records to read only callers.

### Services

| Service | Responsibilities |
| --- | --- |
| `CatalogueService` | Products, categories, allergens, availability, image resolution, refusal to delete a referenced product |
| `SlotService` | Slot generation from a location, closures and order counts. `DaySlotLoad` for a date range. Capacity check inside the ordering transaction |
| `OrderService` | Cart to order, state transitions with history, totals, reference generation, cancellation and slot release |
| `CustomerService` | Deduplication by lowercased email, update from the newest order |
| `InvoiceService` | Issue on pickup, gap free yearly numbering, void with a reason |
| `UserService` | Staff CRUD, locked user rules, refusal to delete yourself |
| `DashboardService` | Revenue by day, orders by state, top products, slot utilisation, all as records |

### Ordering rules

Placing an order revalidates everything, because a cart may have been open for an hour: product still available, price snapshot taken now, lead time respected, the day not closed, the slot not full. The capacity check and the insert happen in one transaction, and a lost race surfaces as a friendly "that slot just filled up" rather than a constraint violation.

### Money

`Money` is a record of cents plus currency. VAT is computed per line at the line's snapshot rate, rounded half up at the line, then summed. The order total is the sum of the lines, never a recomputation from a gross figure. Every rounding rule has a unit test with the awkward cases.

### Dataset

Generated by `scripts/generate-dataset.mjs`, shifted by whole weeks at boot, integrity asserted by `DatasetIntegrityTest`. See `02-data-set.md`.

## Edge cases

| Scenario | Behaviour |
| --- | --- |
| Two orders race for the last slot | One succeeds, the other gets a domain exception naming the slot |
| A product price changes after a line was created | The line keeps its snapshot. New lines get the new price |
| A customer orders twice with the same email and a new phone | One customer row, phone updated, both orders attached |
| An order is cancelled | The slot is freed and the history records who cancelled it |
| An invoice is voided | The number is never reused. A new invoice gets the next number |
| The database has data already | The dataset scripts do not run again, and the date shifter is idempotent |

## Acceptance criteria

### AC1: Schema and entities agree
- [x] The application starts with `ddl-auto=validate` and no schema warning
- [ ] `schema.sql` runs on both H2 and PostgreSQL

### AC2: The dataset is honest
- [x] All checks in `DatasetIntegrityTest` pass
- [ ] After a boot on any day of the week, no order sits on a closed day, and today has orders in several states
- [ ] The same generator seed produces byte identical SQL files

### AC3: Ordering is safe
- [x] Placing an order into a full slot fails with a domain exception and no partial write
- [ ] Concurrent placement into the last free slot leaves exactly one order

### AC4: Money is exact
- [x] For every invoice in the dataset, gross equals net plus VAT
- [ ] Line rounding uses half up and is asserted against a table of awkward values

### Still open

- Only H2 is ever exercised. `schema-postgresql.sql` and `data-postgresql.sql` are written and nothing runs them, in the suite or in CI, so the claim that the schema works on both is untested.
- The dataset is checked for closed days and weekday alignment, but nothing asserts the demo quality half of that criterion, that today always has orders in several states.
- The generator scripts exist under `scripts/`. Nothing asserts that the same seed produces byte identical SQL, so a regenerated dataset would be reviewed by eye.
- `SlotConcurrencyTest` fills a slot sequentially and proves the refusal names the slot and that capacity is never exceeded. It does not run two threads at the last free place, which is the interesting half of DOM-03.
- Rounding is exercised through real invoices, not against a table of awkward values chosen to break it.
