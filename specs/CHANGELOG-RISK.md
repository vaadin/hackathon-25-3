# Preview and beta API register

Everything in this application that depends on an API that is preview, experimental, beta or otherwise likely to move before 25.3 goes final. When the release lands, this is the checklist.

| API | Status in 25.3.0-beta1 | Used in | What to recheck at GA |
| --- | --- | --- | --- |
| Breadcrumbs | Preview, flag `breadcrumbsComponent`, requires server restart | Epic 05 checkout trail, epic 06 order detail | Flag removal, router mode API, item API |
| Switch | Preview, flag `switchComponent`, requires server restart | Epic 07 product and user grids | Flag removal, value change semantics |
| AI components | Flag `aiComponents`. Core free, controllers commercial, and the commercial half validates its licence inside its constructor with a five minute blocking call, so `base/CommercialLicence.java` asks first and the view does without the controller when there is no key | Epic 12 | Flag removal, whether the split of free and commercial moved, and whether the licence check still blocks |
| Table, TableRow, TableCell | New in 25.3, replaces NativeTable | Epic 08 summaries, epic 10 print view | API shape of `bindChildren` on table sections |

## Rules that follow from this table

1. Every API in this table is used through a thin adapter in `base`, so a signature change is a one file fix.
2. Each preview component has a free, non preview fallback behind a factory: Breadcrumbs falls back to an anchor trail, Switch to a themed Checkbox. A removed or renamed flag degrades the demo, it does not break the build.
3. Both previously unverified APIs were spiked during epic 01 and exist as specified. No epic needed amending.
4. A nightly build runs against the newest 25.3 prerelease, so drift is caught by CI and not on stage.

## Project risks

| Risk | Mitigation |
| --- | --- |
| Beta APIs change between beta1 and GA | The adapter rule above, one pinned `vaadin.version` property, nightly prerelease build |
| Commercial licensing blocks a machine | Development and the whole test suite run with no licence, because the licence is enforced in the browser and in the production frontend build. A production build needs a Pro subscription, deliberately, see Licensing in `00-overview.md` |
| The assistant is not deterministic | The default run has no model at all, so nothing in it depends on one. One live tagged test, excluded from CI |
| No network at the demo | Mock provider, seeded data, no CDN dependency. Provider switch is one click |
| Browserless and TestBench balance drifts | The IT list in `08-testing.md` is closed at ten classes and changes only by editing that document |
| The dataset stops being reviewable | Capped at 1400 orders and about 2 MB, regenerated by a committed script, never hand edited. The `bulk` profile handles volume |
| Specifications and code drift apart | `SpecConsistencyTest` fails the build when a feature document names a test class that does not exist |
| Fourteen epics do not fit the time available | Phase 1 is demoable alone. Phase 2 is cut from the bottom of the priority order in `00-overview.md` |
